# Development tools

The repository's Bazel-managed development environment makes tools available
on `PATH` through direnv. These include `aspect`, `buildozer`, `ibazel`,
`java`, `jar`, `playwright`, and `pnpm`.

The root `package.json` pins pnpm in `packageManager`. Both Corepack and Bazel
read this field, so Renovate updates their shared version in one place.

[`tools/BUILD.bazel`](../tools/BUILD.bazel) is the source of truth for the
tools that this repository adds to `PATH`. The environment is generated by
[bazel_env.bzl](https://github.com/buildbuddy-io/bazel_env.bzl).

## Bazel rule conventions

Load Java rules from `//tools/bazel:java.bzl`, just as JavaScript rules use
`//tools/bazel:js.bzl`. The `java_library` and `java_binary` wrappers forward all
attributes unchanged; `java_test_suite` supplies the repository's JUnit defaults.
Keep upstream rule loads in these shared modules.

Globs must match by default. Use `allow_empty = True` only for intentionally
optional inputs, such as a library's assets or test fixtures, and explain why
they are optional. Remove unused patterns instead of disabling strict glob
checking for the repository.

## IntelliJ Bazel compatibility

The shared configuration no longer enables `--experimental_google_legacy_api`.
Repository target analysis with Bazel 8.8.0 succeeds without it. An interactive
IntelliJ sync has not been verified as part of this change; CLI validation does
not establish compatibility with every IDE plugin version.

If your IDE still injects this flag, switching between IDE and terminal commands
can cause repository remapping and reanalysis. In that case, add
`common --experimental_google_legacy_api` to your ignored `user.bazelrc` to align
the commands while that plugin requires it.
