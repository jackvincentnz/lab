# GitHub issues

Avoid deciding acceptance criteria unless the user has asked you to or confirmed that they want you to do so.

The user uses issues for:

- Tracking upstream issues and PRs to know when to fix things.
- Capturing loose ideas about what to work on next.
- Describing high-level problems that need a solution.
- Recording clear solutions that are ready for delivery.

Let the structure and level of detail fit the conversation. No fixed template or required sections. Keep exploratory ideas open, and preserve an explicitly chosen solution when that is the intent.
